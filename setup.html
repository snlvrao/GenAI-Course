Three things that trip everyone up

1

What a virtual environment is

Python installs libraries into one shared pile. Two projects needing different versions of the same library then fight, and one breaks. A virtual environment is a folder holding a private copy of Python and its own libraries, so this course cannot break anything else and nothing else can break it. It is called .venv. If things get tangled, delete that folder and redo one step. That is the whole recovery plan.

2

What activating means

Activating tells your terminal that python means the one in this folder. You will see (.venv) at the start of your prompt. If you do not see it, you are using the wrong Python, which causes most "but I installed it" errors. It lasts until you close the window, so you do it each time you sit down.

3

Why keys never go in code

An API key is a password that can spend money. Typed into a Python file it ends up in backups, screenshots, and public repositories where bots find it within minutes. Instead it goes in a plain text file named .env that your code reads at startup and you never share. It is just lines like GROQ_API_KEY=abc123.

3

What you are giving up, and what you gain

A model on your laptop is slower than a hosted one and noticeably weaker, and below about 3 billion parameters it becomes unreliable at choosing tools, which matters from Module 9 onward. In exchange you get no account, no key, no bill, no rate limit, and it keeps working with the network off. Every lab is built to run this way.

Check you have Python

Open a terminal. On Windows press Start, type PowerShell, press Enter.

terminal
python --version

You want 3.10 or newer. Anything up to 3.14 works. If that errors, install Python from python.org and tick "Add Python to PATH" on the first installer screen.

About versions

Every package in this course installs as a ready-made file on Windows, macOS and Linux for Python 3.10 through 3.14, with no compiler and no build tools. That includes PyTorch, which used to be the painful one. The one exception is noted where it appears.

Make the environment

Everything you make in this course lives in one folder, my-work, and that includes the environment. Nothing outside it is yours to edit, so you can back up or delete your work without touching the course.

Windows PowerShell
cd path\to\GenAI-Course
python -m venv my-work\.venv
.\my-work\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
Mac or Linux
cd path/to/GenAI-Course
python3 -m venv my-work/.venv
source my-work/.venv/bin/activate
python -m pip install --upgrade pip
Windows: expect the third line to be refused the first time

Fresh Windows installs block local scripts, so Activate.ps1 fails with "running scripts is disabled on this system". That is the default, not something you broke. Allow scripts for your own user, which needs no administrator rights, then run the activate line again:

one-time fix, then retry the activate line
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

If you would rather not change that setting at all, you never have to activate. Call the environment's own Python by its path instead, which works with no policy change:

the alternative
.\my-work\.venv\Scripts\python.exe -m pip install openai
.\my-work\.venv\Scripts\python.exe hello_llm.py

Your prompt should now start with (.venv). Activation lasts only for the window you ran it in, so you run that activate line again at the start of every session.

Install Ollama and pull a model

Ollama downloads a model file to your disk and serves it from your own machine. No account, no key, no bill. Install it from ollama.com, then:

terminal
ollama pull llama3.2:3b

# check it answers before you write any Python
ollama run llama3.2:3b "say hello in five words"

The download is a few gigabytes and happens once. After that it works with your network off. The 3b is the size tag: 3 billion parameters.

Which model to pull
modeldiskgood for
llama3.2:3b~2 GBThe default here. Handles tool calling well enough for Modules 9 to 15.
qwen2.5:3b-instruct~2 GBA good second model, and the one to pull for the Module 1 mini-project, which compares two.
llama3.2:1b~1.3 GBOnly if disk is tight. Tool calling is a coin flip, so Modules 9 to 15 will frustrate you.
qwen3:4b~2.5 GBThinking model, see the warning below. Capable, but it does not behave like the others out of the box.
Thinking models need more room, and qwen3 is one

Some models write out their reasoning before they answer. Run ollama run qwen3:4b "say hello in five words" and you get a wall of "Thinking..." before the five words arrive. That is the model working normally, not a fault.

It matters for the labs because the reasoning is counted and billed as output, and because providers return it in a separate field. If the model uses up its token budget thinking, the answer field comes back empty. Measured here: asked for five words with the course's default budget of 800 tokens, qwen3:4b spent all 800 on reasoning and returned no answer at all. Given 3200 it answered fine.

So pick a model that answers directly while you are learning the plumbing, and meet thinking models properly in Module 5, where the course measures what that reasoning costs. If you do want to use one now, ask for more room: chat(prompt, max_tokens=3200). The course helper detects the empty answer and tells you which of the two fixes you need, rather than handing you a blank string.

Ollama must be running

The Windows and Mac installers usually start it for you and keep it running in the background. If a lab reports that it cannot connect, run ollama serve in a separate terminal and leave it open. It listens on port 11434, which is where the course helper already points.

Write your .env

One line. There is no key, because there is no account. Save it as my-work/.env, beside the environment you just made. The labs find it by looking in the folder you are standing in and then working upwards, so anywhere inside my-work can see it.

my-work/.env
# Everything runs on your machine. No key, no internet, no limits.
LLM_PROVIDER=ollama

# Optional: only if you pulled something other than the default.
# LLM_MODEL=qwen3:4b

Create a file called exactly .env inside my-work, beside the environment you made. The name is a dot followed by "env", nothing before the dot.

Never commit this file

If you put this folder under version control, add a .gitignore containing the single line .env. One is already in the course folder. Leaked keys are the most common expensive mistake in this field, and they leak from repositories more than anywhere else.

When something goes wrong

?

"No module named …" for something you installed

You are in the wrong Python. Does your prompt start with (.venv)? If not, activate and try again. This is the most common problem and it is never actually about the package.

?

It works when you run it, fails when something else starts it

Same cause in disguise. When one program launches another, the word python resolves against your system settings, not your environment, so the child process starts without your packages. Inside Python use sys.executable, which always means the interpreter you are running in. Module 13 hits this for real.

?

The install is huge and slow

That is sentence-transformers pulling in PyTorch, a few hundred megabytes. One-time cost, and it buys you free offline embeddings for the rest of the course. Let it finish.

?

"Model not found"

Model names are retired and renamed faster than anything else here. Nothing is broken. Open your provider's model list, pick a current one, and set LLM_MODEL= in .env. No code changes.

?

Suddenly rate limited

You hit the daily cap. Wait, switch LLM_PROVIDER to your other free provider, or install Ollama and set it to ollama to remove limits entirely.

?

Connection refused on port 11434

Ollama is not running. Run ollama serve in a separate terminal and leave it open. On Windows it also appears in the system tray.

?

The agent labs behave badly

Small local models are genuinely weaker at choosing tools. Before assuming your code is wrong, try the same lab once on a free hosted key. If it works there, your code is fine and you have learned something real about model size. Then switch back.

?

You want to start over

Delete the .venv folder and redo the environment step. Nothing else on your computer is affected and your own work is untouched, because it lives outside that folder.

How to remove all of it

No uninstaller, no registry entries, no background services.

  • Delete the .venv folder. Every Python package above is gone.
  • Remove Ollama like any other application, and delete its downloaded models (on Windows they sit in %USERPROFILE%\.ollama).
  • Delete .env, and revoke the key in your provider's console so it cannot be used again.
  • Notes and progress live in your browser. The Reset everything button on the home page clears them.
